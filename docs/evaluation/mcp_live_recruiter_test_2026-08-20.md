# MCP Live Recruiter Test — 20 August 2026

## Outcome

Tom's first ChatGPT workspace test proved that the published read-only MCP app
could authenticate, list companies, retrieve candidates, fetch candidate
profiles, and retrieve a current CV reference. The final Senior Data Engineer
answer contained candidate IDs, source distinctions, and evidence-backed fit
summaries, but the tool sequence was too slow and the company directory exposed
unreviewed source labels without identifiers or provenance.

## Privacy-safe production evidence

The metadata-only MCP audit table recorded:

- three failed `search_candidates_for_role` calls lasting `240,512 ms`,
  `159,145 ms`, and `224,198 ms`
- a fourth successful candidate search lasting `24,818 ms`
- six subsequent candidate-profile calls lasting between `5,167 ms` and
  `9,053 ms` each
- one current-resume lookup lasting `746 ms`
- warm company-directory calls completing in `14 ms`

The audit trail did not contain the role brief, candidate content, identifiers,
or credentials. Its old generic `internal_error` category was insufficient to
reconstruct the exact failed stage, which motivated the bounded failure-stage
telemetry change.

The questionable company labels were exact canonical database values rather
than names generated by ChatGPT. Four were linked to Dropbox CV extraction and
one to Linked Helper. The canonical rows remain intact for provenance and
reconciliation; the MCP directory now returns IDs, source categories, freshness,
and conservative review flags.

## Implemented response

- MCP candidate search is now retrieval-only and cannot trigger the slower
  model-backed shortlist in the same call.
- OpenAI embeddings have a `10` second timeout and zero hidden SDK retries.
- Semantic failure falls back to deterministic full-text retrieval.
- Initial candidate results include batched skills, recent employment, CV
  availability, source provenance, freshness, and match evidence.
- Company prefix matching is a true case-insensitive starts-with operation.
- Company results include canonical IDs, bounded provenance and quality flags.
- MCP failure audits include only bounded failure stage/category metadata.

## Revised local live benchmark

The revised Senior Data Engineer retrieval path was run three times against the
configured Supabase and embedding provider, with model shortlisting disabled:

| Run | Duration | Results | Skills returned per result |
| --- | ---: | ---: | ---: |
| 1 | 24,034 ms | 5 | 16 |
| 2 | 19,998 ms | 5 | 16 |
| 3 | 22,272 ms | 5 | 16 |

All runs completed successfully and returned evidence in the initial response.
This removes the observed multi-minute model retry path and makes the six
sequential profile reads unnecessary for the tested question. The deployed
ChatGPT app still needs a tool rescan/republish followed by the same three-run
workspace test before recruiter relevance review resumes.
